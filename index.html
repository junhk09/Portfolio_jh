무게 기반 자동 분류 시스템

6인 팀
2026.04 – 2026.05 · 서울기술교육센터

담당역할: 로봇팔(6축) 구동 시퀀스 로직 설계, PCA9685 서보모터 제어, FreeRTOS Robot Arm Task 분리 및 메모리(Heap/Stack) 최적화

사용 기술: C/C++, STM32, FreeRTOS, Git

개요

로드셀(Load Cell) 센서로 물체 무게를 실시간 측정하고, 측정값에 따라 컨베이어 벨트 구동과 로봇팔 피킹(Picking) 동작을 유기적으로 제어하는 통합 자동화 솔루션. 센서 데이터 신뢰성을 높이는 필터링 알고리즘과 팀 단위 형상 관리(Configuration Management)에 중점을 두고 진행했습니다.

시스템 파이프라인

Sensing 로드셀 아날로그 신호 수집 → ADC(AD002) 디지털 변환 Processing MCU 내 이동 평균 필터(Moving Average) 적용, 무게 기준값 기반 제어 로직 Acting 컨베이어 벨트 모터 구동 + 6축 로봇팔 분류(피킹) 시퀀스 제어

주요 기능

  • 정밀 무게 측정: 로드셀 + AD002 변환 모듈로 아날로그 데이터 수집
  • 신호 처리 알고리즘: 이동 평균 필터로 센서 노이즈 억제, 측정 정밀도 향상
  • 실시간 통합 제어: 측정 무게에 따라 컨베이어 이송·로봇팔 분류 동작 실시간 트리거
  • 협업 최적화: 헤더(.h)/소스(.c·.cpp) 분리로 병합 충돌 최소화하는 모듈 구조 설계

Trouble Shooting

문제 · 로봇팔 반복 동작 시 2회차부터 로테이터(5번 모터) 정지
원인 · 사이클 종료 시 초기 각도 복귀 로직 누락 → 현재·목표 각도 동일해 명령은 실행되나 움직임 없음
해결 · 매 사이클 종료 시 전 축 초기 각도 복귀 로직 추가
문제 · 로봇팔 동작 중 CLI 명령 입력이 한 박자 지연 처리
원인 · CLI 처리와 로봇팔 제어가 단일 루프에서 순차 처리되는 구조적 문제
해결 · FreeRTOS에서 CLI Task와 Robot Arm Task를 분리해 병렬 처리 구조로 개선
문제 · Task 분리 후 로봇팔 Task 자체가 실행되지 않음
원인 · ① HAL_Delay(blocking)가 태스크 스케줄링 저해 ② 전체 Task 소요 Stack(18,432B)이 Heap(15,360B) 초과
해결 · ① HAL_Delay → osDelay(non-blocking) 전환 ② configTOTAL_HEAP_SIZE를 24,576B로 증설

SmartFarm

2인 팀
2026.05 – 2026.06 · 서울기술교육센터

담당역할: 아두이노(ESP-01 WiFi)–라즈베리파이 TCP 통신, 라즈베리파이 TCP·REST API 서버 구현, MariaDB 데이터 관리, Apache 웹서버·대시보드 및 mjpg-streamer 웹캠 스트리밍 연동

사용 기술: 라즈베리파이, STM32, 아두이노 우노, MariaDB, Apache2, Git, C/C++

개요

라즈베리파이, 아두이노(ESP-01 WiFi), STM32 F411RE를 결합해 온습도·조도·화재를 실시간 감지하고, 감지된 데이터에 따라 RGB LED·DC모터·워터펌프·부저를 자동 제어하는 IoT 스마트팜 시스템. 라즈베리파이가 TCP·REST API 서버 역할을 겸하며 MariaDB에 센서 이력을 저장, 웹 대시보드에서 실시간 웹캠 스트리밍까지 제공합니다.

시스템 아키텍처

Arduino(ESP-01 WiFi) --TCP--> RaspberryPi(iot_server) ├─ MariaDB (센서 데이터 저장) ├─ HTTP API (Port 8080) └─ Bluetooth RFCOMM --> STM32 F411RE(HC-06) └ RGB LED·부저·DC모터·워터펌프 Browser --> RaspberryPi IP --> Apache(Port 80) --> dashboard.html └ mjpg-streamer 스트림 임베드 (Port 8090)

통신 프로토콜

Arduino → Server (TCP) 로그인: [S:PASSWD] 센서전송: [KJH_SQL]SENSOR@조도@온도@습도@불꽃 Server → STM32 (Bluetooth) CMD:LED:R/G/B CMD:MOTOR:ON/OFF CMD:BUZZER:ON/OFF CMD:PUMP:ON/OFF CMD:LIGHT:HIGH/MID/LOW STM32 → Server (Bluetooth) STATUS:MOTOR:ON:SPD:75:PUMP:OFF:LED:G:BUZZ:OFF REST API GET /api/sensors 최근 센서 데이터 GET /api/actuators 액추에이터 상태 GET /api/status 계절 + 최신 센서 POST /api/control 액추에이터 제어

주요 기능

  • 온도·습도·조도·화재 데이터 실시간 수집 → MariaDB 저장
  • 계절별 RGB LED 자동 제어 (10℃ 이하 파랑 · 10~25℃ 초록 · 25℃ 이상 빨강)
  • 화재 감지 시 부저 ON + 워터펌프 5초 자동 가동, 해제 시 자동 종료
  • 습도 20% 이하 시 워터펌프 자동 급수, 조도 기반 CDS 연동 LED 밝기 제어(TIM3 PWM)
  • 실시간 웹캠 스트리밍 (mjpg-streamer, 640×480 · 15fps) 대시보드 임베드

Trouble Shooting

문제 · STM32 TIM1 채널 PWM이 전혀 출력되지 않음
원인 · TIM1/TIM8은 Advanced-control 타이머라 Main Output Enable(MOE) 비트가 별도로 꺼져 있음
해결 · __HAL_TIM_MOE_ENABLE() 호출 추가, 모터 드라이버 PWM 정상 출력 확인
문제 · 라즈베리파이 GPIO만으로 워터펌프/릴레이가 구동되지 않음
원인 · GPIO 출력 전류(수 mA)로는 릴레이 코일을 직접 구동할 수 없음
해결 · MPS2222A 트랜지스터 스위칭 회로 추가, GPIO로 트랜지스터를 구동해 릴레이 코일 전류 공급
문제 · 아두이노 ↔ ESP-01 시리얼 통신 데이터가 깨져서 수신됨
원인 · SoftwareSerial 통신 속도(Baud Rate)가 ESP-01 기본 설정과 불일치
해결 · 양쪽 baud rate를 동일하게 맞추고 통신 속도를 낮춰 재설정, 정상 수신 확인

원자의 세계 속으로

5인 팀(개발자 2·PM 1·디자이너 2) · VR
2025.03 – 2025.05 · 한성대학교 캡스톤

담당역할: 개발자로서 Meta Quest3 관련 기능 구현, GUI 구현, GitHub 형상 관리 담당

사용 기술: Unity, C#, UModeler, Blender, Meta Quest3

개요

Unity 엔진으로 원자의 세계를 3D 시각화하고, 사용자가 원자를 직접 선택·조작해 분자를 형성하고 화학식을 구성할 수 있는 VR 교육 콘텐츠. 컨트롤러 없이 핸드 트래킹만으로 상호작용해 몰입감을 높였고, 학습자가 원자 간 결합과 분자 구조를 직관적으로 이해하도록 설계했습니다.

주요 기능

  • 오른손 주먹을 쥐고 손바닥이 자신을 향하면 원자 소환용 주기율표 등장
  • 주기율표에서 원자를 선택하면 해당 원자가 소환됨
  • 검사대 위에 원자·분자를 올리면 관련 설명을 확인 가능
  • GUI로 원하는 분자를 선택 후 필요한 원자를 가져와 조합, 반응식을 풀며 화학 개념 학습

Trouble Shooting

문제 · GitHub 형상 관리 시 merge 충돌 발생
원인 · 브랜치는 나눴지만 같은 Scene 파일에서 작업해 충돌 발생
해결 · Scene 자체를 새로 생성해 각자 따로 작업 후 merge하는 방식으로 해결
문제 · 서로 다른 원자를 올려도 결합 안 되거나, 무관한 원자끼리 결합되는 오판정
원인 · 결합 가능 여부를 if-else 하드코딩 → 원자 종류가 늘수록 조건문 폭증, 개수 조건(H2O 등) 누락
해결 · Dictionary<string, MoleculeData> 구조로 리팩토링, "원자 종류+개수"를 키로 관리해 데이터 추가만으로 확장 가능하도록 개선
